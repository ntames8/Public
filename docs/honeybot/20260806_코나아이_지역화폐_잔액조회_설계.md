# 코나아이(지역화폐) 잔액 조회 기능 — 설계

- 작성일: 2026-08-06
- 관련 요구사항 문서: `20260806_코나아이_지역화폐_지출조회_요구사항.md`
- 상태: 설계 초안, 미착수

## 1. 확인된 스코프

요구사항 문서 작성 후 사용자와 확인한 내용:

- "예산 상황" = **단순 충전 잔액 조회**만 (월별 목표 대비 비교, 이력 저장 없음)
- 화면 경로 (사용자 제공): **내 자산 → 포인트.머니 → 교통.지역화폐 → 코나아이** — 해당 화면에서
  바로 금액이 보이거나, 눌러서 상세내역에서 봐도 됨
- 검증 범위: **컬렉터 로직만 격리 검증**하면 충분 (텔레그램 봇 프로세스 두 개를 같은 토큰으로
  동시 폴링하면 409 Conflict 나는 것 확인됨 — 별도 봇 토큰/E2E 불필요)
- grep으로 확인: 코나아이/지역화폐/잔액-트래킹 관련 기존 코드 전혀 없음 — 완전 신규 기능

목표: 운영 중인 프로덕션 honeybot을 건드리지 않고 별도 워크스페이스에서 안전하게 개발·검증한 뒤
병합하는 것.

## 2. 기능 구현

**`collector/naver_app_collector.py`** — `NaverAppCollector`에 `get_kona_balance(self) -> int` 메서드
추가 (기존 `get_screen_status()`/`get_battery_info()`처럼 `collect()`와 무관한 독립 메서드로 —
`BaseCollector.collect()`는 `list[Transaction]`을 반환해야 하므로 단일 잔액 숫자를 억지로 끼워 넣지
않음).

재사용할 기존 헬퍼: `_wake()`, `_reset_app()`, `_get_ui_xml()`, `_find_text()`, `_tap()`,
`_screen_off()`, 그리고 PFMS 플로우가 이미 쓰는 로그인/PIN 처리(`LoginRequiredError`, `_enter_pin`,
`config.NAVER_PAY_PIN`) — 내 자산 진입 시 같은 PIN 게이트가 뜰 가능성이 높으므로 동일 처리 재사용.

**구현 0단계 (필수 선행 작업)**: 내 자산 → 포인트.머니 → 교통.지역화폐 → 코나아이로 가는 정확한
탭 시퀀스 또는 직접 딥링크 URL(PFMS가 쓰는 `https://new-m.pay.naver.com/pfms/statements`처럼)이
있는지 **실기기에서 `adb shell uiautomator dump`로 직접 확인 후 구현**. 이건 계획 단계의 공백이
아니라 원래 이런 류의 UI 자동화 기능의 첫 구현 단계임.

**신규 핸들러 `bot/handlers/kona_balance.py`** — `bot/handlers/phone_status.py`의 2폰 fan-out 패턴과
`bot/handlers/sync.py`의 lock 획득/해제 패턴을 그대로 조합:
- `PHONES` 리스트는 새로 정의하지 말고 `bot.handlers.phone_status`에서 import해서 재사용
- 폰별 스레드 함수에서 `DeviceLock(device_id)` 생성 → `is_locked()` 체크 → 잠겨있으면 그 폰 줄만
  `format_lock_busy(info)`로 표시하고 넘어감 (전체 실패시키지 않음, gather 결과에 부분 실패 허용)
- 비어있으면 `device_lock.acquire({...})` → `try/finally`로 `device_lock.release()` 후
  `NaverAppCollector(device_id=device_id).get_kona_balance()` 호출
- `asyncio.gather(*(asyncio.to_thread(...) for ... in PHONES))`로 두 폰 병렬 조회 (기존
  `phone_status_handler`와 동일 패턴)
- 조회 1회성 탭 동작이라 짧으므로 `PROCESS_LOCK`까지는 불필요, `DeviceLock`(기기 단위, 프로세스 간)
  만으로 충분 — 다만 일관성을 위해 필요하면 추가 검토

**`bot/main.py`** — `CommandHandler` 등록 + `set_my_commands([...])`(~228번째 줄)에 항목 추가.
명령어 이름: **`/konabalance`** (텔레그램 명령어는 ASCII만 허용 — 기존 확인된 제약, `phonestatus`/
`screen`/`sync`와 네이밍 일관성 유지).

## 3. Device lock 수정 — 테스트 안전성 확보 (겸 일반 개선)

**문제**: `collector/device_lock.py:28` `OWN_PROGRAM = "honeybot"`은 하드코딩 상수라, 별도 클론에서
같은 코드를 실행해도 똑같이 `"honeybot"`으로 자신을 식별함. `is_locked()`(65번째 줄)가
`info.get("program") == OWN_PROGRAM`이면 "내가 이미 점유 중"으로 보고 **그냥 통과**시키기 때문에,
프로덕션이 실제로 폰을 쓰고 있는 도중에 테스트 클론이 같은 폰을 아무 대기 없이 건드려 충돌할 수
있음 — `stockmonitor` vs `honeybot`은 구분하지만 honeybot-프로덕션 vs honeybot-테스트는 구분 못 함.

**수정**:
- `config.py`에 `LOCK_PROGRAM_NAME: str = os.environ.get("LOCK_PROGRAM_NAME", "honeybot")` 추가
  (기본값 유지 → 프로덕션 `.env` 변경 불필요, 하위호환)
- `collector/device_lock.py`의 `OWN_PROGRAM` 상수 사용 3곳(65, 85, 119번째 줄)을
  `config.LOCK_PROGRAM_NAME`을 호출 시점에 읽도록 변경 (모듈 로드 시점 상수 대신, `__init__`에서
  이미 `import config`를 지연 임포트하고 있으므로 그 지점 활용)
- `bot/handlers/phone_status.py`의 `_PROGRAM_LABELS`(표시용 라벨 매핑)는 변경 불필요 — 테스트
  클론은 자기 `.env`에서만 다른 값 사용

## 4. 격리된 테스트 워크스페이스

- 위치: `~/code/daily/honeycard-test` (문서 호스팅용 `~/code/daily/pages/`와 명확히 분리된 별도
  디렉터리)
- `git clone https://github.com/ntames8/honeycard_bot.git ~/code/daily/honeycard-test`
- 새 브랜치 `feat/kona-balance`를 `main`에서 생성해 체크아웃
- `.env`: `.env.example` 복사 후 `NAVER_APP_DEVICE_ID`, `PHONE2_DEVICE_ID`, `NAVER_PAY_PIN`은 실제
  값 그대로(같은 실물 폰이므로), `LOCK_PROGRAM_NAME=honeybot-test` 추가. `TELEGRAM_TOKEN`은
  **비워도 됨** — 컬렉터 로직만 테스트하므로 `bot/main.py`를 아예 안 거침
- `DB_PATH`는 `config.py` 기본값이 저장소 디렉터리 기준 상대경로라(`Path(__file__).parent`),
  클론만 다른 디렉터리에 하면 자동으로 별도 `honeycard.db` 사용 — 추가 설정 불필요
- 검증 스크립트: 봇 프로세스/폴링 없이 컬렉터를 직접 호출
  ```python
  from collector.naver_app_collector import NaverAppCollector
  c = NaverAppCollector(device_id="R3CR8051NNJ")
  print(c.get_kona_balance())
  ```
  두 폰 각각에 대해 실행 — 409 충돌 이슈 원천 회피
- 정확성 검증: 스크립트 결과와 폰 화면에 실제 보이는 잔액을 육안으로 대조
- Lock 안전성 검증: 운영 클론에서 실제로 lock을 잡은 상태(`/sync` 실행 중이거나
  `DeviceLock(device_id).acquire({...})` 수동 호출)를 만든 뒤, 테스트 클론 스크립트를 실행해
  `is_locked()==True`(program이 `"honeybot"`이고 자신은 `"honeybot-test"`라 "다른 프로그램 사용
  중"으로 인식)를 감지하고 충돌 없이 대기/스킵하는지 확인
